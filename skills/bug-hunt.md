# 숨은 버그 헌트 에이전트 - Codex 협업 데이터 정합성 점검

"정상 동작하는 줄 알았던" 기능의 **예상치 못한 엣지·정합성 버그**를 Codex와 함께 잡아낸다.
코드 정적 분석(Codex)과 실제 실행 검증(Playwright/API)을 **교차**하여, 추측이 아닌 **실행 증거**로 확정한다.

> quick-fix(보고된 버그 1건 수정)·flow-check(전체 플로우 E2E)·mega-audit(종합 5-Phase)와 다르다.
> 이 에이전트는 **아무도 신고하지 않은 숨은 버그**(돈·재고·상태 정합성, API 레벨 방어 공백, 엣지)를 능동 발굴한다.

## 핵심 원칙 (위반 금지)
1. 🤝 **Codex 협업**: Codex가 코드 정적 버그헌트 → 클로드가 라이브 재현/반박. 단독 판단 금지.
2. 🔬 **실행 증거 필수**: "코드상 맞다"로 PASS 금지. 실제 API 호출/UI 클릭 결과(상태코드·DB값)를 첨부.
3. 🛡️ **운영 데이터 보호**: 실데이터 운영 DB일 수 있음. 반드시 `[테스트]` 더미 생성 → 검증 → **삭제(cleanup)**. 실고객/실예약 파괴·완료·삭제 금지.
4. ⚖️ **의도된 정책은 버그 아님**: CLAUDE.md에 명시된 의도적 동작(예: "자유 입력 정책 — 음수/0 허용", "재고 부족 허용")은 false-positive로 **반박** 처리.
5. 📋 **추측 금지**: 확실치 않으면 [의심] 표기 + 추가 검증.

인자: $ARGUMENTS
- 점검 대상: "전체"(기본) 또는 특정 도메인(예: "견적서 재고 매출") / 파일 경로
- `--fix`: 사용자 승인 후 발견 버그 수정
- `--deploy`: 수정 + 라이브 재검증 통과 시 배포까지 (프로젝트 배포 규칙 따름)

## Phase 0: 스코프 + 알려진 정책 파악

1. **CLAUDE.md / docs 정독** → 이미 알려진 주의사항·의도된 정책 목록화 (중복·오탐 방지의 핵심).
   - 예: "자유 입력 정책(범위검증 제거)", "재고 부족 허용", "KST 합성 호출 금지" 등.
2. **고위험 영역 식별** (돈·재고·상태·시간이 얽힌 곳 우선):
   - 상태 전이 + 사이드이펙트(완료/취소 시 재고 차감·환불)
   - 금액 invariant (합계 = 항목합 − 할인, cost = sum(costItems))
   - 누적/집계 (재고 cumulative, 매출 집계 대상 필터)
   - 시간/타임존 경계 (KST, 월말, 날짜 정규화)
   - 입력 검증 (FormData→number, enum, NaN/Infinity, partial update 데이터 손실)
   - 백업/가져오기 (필드 누락, 로그 누락, 트랜잭션)
3. 로컬 dev 서버 + 로그인 세션 준비(라이브 검증용). 빌드/타입체크 baseline 확인.

## Phase 1: Codex 정적 버그헌트 (백그라운드)

`codex:rescue`(또는 codex-rescue 에이전트)를 **백그라운드**로 띄워 코드 전수 버그헌트.
프롬프트 골자:
- "코드 수정 금지, 발견 버그만 **심각도(Critical/Major/Minor)+파일:줄+재현조건+근거** 로 보고"
- Phase 0의 고위험 영역을 명시적으로 나열해 집중시킴
- "CLAUDE.md를 먼저 읽어 알려진 정책/주의 파악 후, **새로 의심되는 것** 우선. 확실치 않으면 [의심]."
- "상위 N건 우선순위화"

Codex가 도는 동안 Phase 2를 병렬 진행(코드 읽기 vs 라이브 — 비충돌).

## Phase 2: 라이브 헬스 + Invariant 스윕 (병렬)

실제 실행으로 현재 데이터 건강 상태를 측정(읽기 전용):
- **API 헬스 스윕**: 핵심 GET 엔드포인트 전부 호출 → 200 + 구조 확인 (500/형태 이상 즉시 포착). 인증 세션으로 `fetch` (Playwright `browser_evaluate` 또는 curl+쿠키).
- **Invariant 검증**:
  - 매출: `summary.invariantOk === true`, 집계 대상 상태 필터 정확
  - 재고: 음수 재고 0건 (오일 cumulativeIn−cumulativeUsed ≥ 0, 부품 quantity ≥ 0)
  - 대시보드 vs 목록 카운트 일치
  - 합계 invariant 표본 확인
- 주요 페이지 렌더 + 콘솔 에러 0 (favicon 등 외부 404는 무해 분류).

## Phase 3: Codex 발견 × 라이브 교차검증 (핵심)

Codex 결과 도착 후, **각 항목을 하나씩 라이브로 확정/반박**:
- **확정(CONFIRMED)**: 더미 데이터로 실제 재현. 예) 더미 견적 생성 → discount만 PUT → totalAmount 미변경 확인 → 삭제. 상태코드·DB값 증거 첨부.
- **반박(REFUTED)**: ① CLAUDE.md 의도 정책에 해당하거나 ② 라이브에서 재현 안 됨. 근거 명시.
- **실제 위험도 재평가**: "API로는 깨지나 UI 정상 경로는 안전" 같은 노출도 함께 기록 (수정 우선순위 판단용).
- 모든 더미 데이터는 검증 직후 **삭제 + 잔존 0건 확인**.

분류표 작성:
```
| # | 항목 | 검증(라이브/코드) | 실제 위험 | 판정 |
|---|------|------------------|----------|------|
```

## Phase 4: 보고 → 수정 → 재검증 → (배포)

1. **우선순위 보고**: Critical/Major부터. 각 항목 재현 증거 + 권장 조치.
2. `--fix`(또는 사용자 승인) 시 **AskUserQuestion으로 수정 범위 선택**(multiSelect). 의도 정책 항목은 기본 제외.
3. 수정 → `tsc`/build → **수정한 항목 라이브 재검증**(고친 게 진짜 고쳐졌는지 + 정상 경로 회귀 0). 더미+cleanup.
4. `--deploy` 시 프로젝트 배포 규칙 따름(예: 빅스모터스 = master push + 커밋 `[deploy]` 토큰). 배포 후 프로덕션 헬스체크.
5. 안전한 방어 수정 우선(입력 검증·enum·invariant 재계산). 동작 의미를 바꾸는 변경은 사용자 확인.

## Phase X+1: Codex 대조 검증 게이트 (이미 Phase 1·3에서 협업했으면 생략 가능)
- Codex 미가용 시 자동 스킵, 클로드 단독 분석 명시.
- Phase 1 Codex 결과가 곧 대조이므로, 별도 라운드는 큰 변경/이견 있을 때만.

## 데이터 보호 체크리스트 (종료 전 필수)
- [ ] 생성한 더미 고객/예약/견적 전부 삭제
- [ ] `[테스트]` 검색 잔존 0건 확인
- [ ] 실데이터 상태/재고/금액 변경 0 (읽기 또는 더미만 사용)

## 사용 예시
```bash
/bug-hunt                         # 활성 프로젝트 전체 숨은 버그 헌트 (보고만)
/bug-hunt 견적서 재고 매출         # 특정 도메인 집중
/bug-hunt 전체 --fix              # 발견 + 승인 후 수정
/bug-hunt auto-shop-manager --fix --deploy   # 수정 + 라이브 재검증 + 배포
```

## 산출물
- 버그 분류표(확정/반박 + 재현 증거) + 수정 내역 + 라이브 재검증 결과 + (배포 시) 커밋/배포 확인.
