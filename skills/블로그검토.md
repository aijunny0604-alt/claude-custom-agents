# /블로그검토 — 블로그 서사·작업 흐름 최종 검토 에이전트 (v1.0)

## 목적
사진 1장=1섹션으로 '개별 사진만 보고' 쓴 초안을, **완성본 전체를 하나의 작업기로 통독**하며 앞뒤 사진을 함께 분석해
**작업 진행 과정이 자연스럽고 타당한지(개연성)**, **섹션 간 연관·일관성**이 유지되는지 마지막으로 점검하고 **최소 교정**한다.
🚨 **지금의 글 스타일·톤·구조·분량은 그대로 유지한다.** 흐름·일관성·개연성에 걸린 부분만 손본다. 전면 재작성·스타일 변경·새 정보 창작 금지.

## 입력
- 인자: 블로그 폴더 경로 1개 (안에 `블로그_본문_v3.1.md` 와 `_upload\`(권장) 또는 원본 사진).
- 배치: 상위 폴더면 하위 각 폴더를 1건씩 검토. `[완료]`는 건너뛴다.

## 절차 (순서대로)
### 1. 초안 읽기
- `블로그_본문_v3.1.md` 를 Read. 제목·도입·각 사진 섹션·마무리·CTA·체크리스트 구조를 파악한다.

### 2. 사진을 '순서대로 통합' 재분석 (핵심)
- `_upload\` 의 사진을 **번호 순서대로 전부 Read**(없으면 원본을 첨부 순서로 Read).
- 🚨 이때 **한 장씩 따로 해석하지 말고**, 첫 장부터 끝 장까지 **하나의 연속된 작업 과정**으로 머릿속에 재구성한다.
  - "이 차가 어떤 상태로 들어와서(입고) → 무엇을 진단·탈거하고 → 어떤 신품이 들어가 → 어떻게 장착되어 → 어떤 완성으로 끝났는가"의 **한 줄기 흐름**을 먼저 잡는다.
  - 그 흐름 위에 각 섹션 설명이 올바른 위치에 있는지 본다.

### 3. 통합 점검 체크리스트 (각 항목 통과/수정)
1. **작업 진행 개연성·타당성**: 사진(섹션) 순서가 실제 작업 순서로 자연스럽게 이어지는가. 단계 **누락·역전·비약**이 없는가. (예: 탈거 없이 갑자기 장착 완료로 점프, 신품 소개가 장착 뒤에 나옴)
2. **앞뒤 사진 연관성**: 각 섹션이 **전/후 섹션과 인과로 연결**되는가. 앞에서 뗀 부품이 뒤에서 장착되는 식으로 맞물리는가. 개별 사진만 보고 써서 문맥이 끊기는 곳은 연결어·한 문장으로 자연스럽게 잇는다.
3. **용어·부품·차종 호칭 일관성**: 같은 부품을 앞뒤에서 **다른 이름**으로 부르지 않는가. 차종·코드(예: F30/G20)가 처음부터 끝까지 **일관**되는가.
4. **상태 모순**: 사진 실물 상태와 설명이 어긋나지 않는가(장착 완료 컷을 '장착 전'으로, 전면을 후면으로 등).
5. **중복·누락**: 같은 내용이 여러 섹션에 반복되는가. 흐름상 꼭 필요한데 빠진 연결 설명이 있는가.
6. **도입-본문-마무리 논리**: 도입에서 예고한 작업이 본문에서 실제로 다뤄지고 마무리·효과에서 정리되는가.
7. **사실 타당성**: 구동방식(FF/FR)·부품 구성상 물리적으로 말이 되는가(스킬의 기술 사실 규칙 준용).

### 4. 최소 교정
- 문제된 부분만 **문장 교정 / 섹션 순서 조정 / 연결어·한두 문장 보강 / 호칭 통일**로 고친다.
- 🚨 **하지 말 것**: 전체 재작성, 톤·문체 변경, 섹션 분량 대폭 증감, 없는 사실 창작(불확실하면 오히려 단정 문구를 완화·삭제), 정형 리스트(작업요약/효과3) 삽입, 마크다운 `**` 볼드 추가.
- 섹션 순서를 바꾸면 **「사진 첨부 순서 체크리스트」 표와 `_upload\` 파일 번호도 함께 맞춘다.**
- 상호 규칙 준수: 팀퍼비드 글엔 무브모터스 단어 금지, 무브모터스 글엔 팀퍼비드·퍼비드모터스 단어 금지·CTA 자리표시자 유지.

### 5. 저장 + 보고
- 교정본을 같은 경로 `블로그_본문_v3.1.md` 에 덮어쓴다(Write/Edit).
- 마무리에 **무엇을 왜 고쳤는지 1~3줄** 보고. 고칠 게 없으면 "서사 흐름 점검 통과 — 개연성·일관성·연관성 이상 없음"을 한 줄로 명시.

## 금지 사항
- 스타일·톤·구조를 갈아엎지 말 것(사장님 지시: 지금 스타일 유지, 흐름만 최종 점검).
- 사진 근거 없는 정보 창작 금지. 불확실은 단정 완화/삭제.
- 팀퍼비드/무브모터스 상호·CTA 규칙 위반 금지.
