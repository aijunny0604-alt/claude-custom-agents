## 실행 절차 (반드시 순서대로)

### 0. 사전 점검
1. `$ARGUMENTS`가 비었으면 → 폴더 경로를 사용자에게 1회 묻고 받으면 진행. 묻기 외 추가 질문 금지.
2. PowerShell로 경로 존재 확인:
   ```powershell
   Test-Path -LiteralPath "<경로>"
   ```
   - 없으면 → `C:\Users\MOVEAM_PC\Downloads`에서 유사 폴더 후보 3개 안내 후 종료
   - 있으면 → 다음 단계

### 1. 폴더 스캔 + EXIF 기반 사진 정렬 (v3.4)
```powershell
Get-ChildItem -LiteralPath "<경로>" | Sort-Object Name |
  Select-Object Name, Length, LastWriteTime | Format-Table -AutoSize
```
- 사진(.jpg/.jpeg/.png) / 영상(.mp4/.mov) / 텍스트(.txt) 분리 파악

**사진은 EXIF 기준으로 자동 정렬** (v3.4 필수):
```powershell
python "C:\Users\MOVEAM_PC\claude-custom-agents\scripts\sort_photos.py" "<경로>"
```
- 출력: JSON 배열. 각 항목에 `file / path / shot_at / sort_key / source` 포함.
- `source` 가 `exif` 이면 EXIF DateTimeOriginal 기준, `filename` 이면 파일명 fallback.
- **이 정렬 결과 순서대로** 사진 분석 / 본문 사진 섹션 / 첨부 순서 체크리스트를 구성한다.
- EXIF 정렬과 파일명 정렬이 다른 사진이 1장이라도 있으면 마무리 안내에 한 줄 명시
  (예: "📸 EXIF 시간순으로 정렬했습니다. 카톡 캡처 3장은 파일명 기준 fallback 적용.")

### 2. 메모.txt 우선 읽기 (있다면)
- 폴더 내 `.txt` 파일 전부 Read
- 메모에 다음 정보가 있으면 우선 사용:
  - 차량 / 차량코드 / 번호판 / 작업명 / 주요 부품 / 오너 요청 / 특이사항
- 메모가 한 줄짜리면 → 사진으로 보강 추정

### 3. 사진 분석 (블로그 본문용)
- **모든 사진**을 Read로 한 장씩 시각 분석
- 다음 항목을 메모:
  - 차량 색상 / 차종

### 3.5 영상 분석 (배기음 영상 등) (v3.5.5 신설 — 영상 있을 때 필수)
폴더에 영상(.mp4/.mov)이 있으면 (주로 배기음 영상) 아래로 분석해 본문에 영상 섹션을 만든다.

1. **분석 실행** (영상마다):
   ```powershell
   python "C:\Users\MOVEAM_PC\claude-custom-agents\scripts\video_analyze.py" "<영상 절대경로>"
   ```
   - `_video\<영상명>\` 에 프레임(frame_NN.jpg) 추출 + `analysis.json`(음압/대역) 생성, stdout에도 JSON.
2. **화면 분석**: 추출된 `frame_*.jpg`를 Read로 시각 분석 (배기팁 모양·화염(불쇼)·차량·작업 장면).
3. **사운드 데이터 해석** (analysis.json):
   - `low_band_mean_db`(≤250Hz) vs `high_band_mean_db`(≥2kHz): 저음/고음 어느 쪽이 강조됐는지.
   - `segment_mean_db`(3등분): 뒤로 갈수록 커지면 공회전→가속에서 음압이 치솟는 것.
   - `overall_max_db`: 피크 음압.
4. **본문 영상 섹션 작성**: 형식 `**[영상 — 배기 사운드]** _(영상파일명.mp4)_`, 3~5줄 정중 자연체.
   화면에서 본 장면 + 위 데이터를 근거로 묘사. **첨부 순서 체크리스트 표에도 영상 행을 넣는다.**
5. ⚠️ **과장 금지**: 스크립트는 음압·대역 '수치'만 뽑는다. 실제로 귀로 들은 게 아니므로 "야수 같은 사운드"처럼
   청취한 척하지 말 것. "정확한 사운드는 영상으로 직접 확인해보시길 권합니다" 같은 안내를 한 줄 넣는다.
6. 영상 속 **말소리(설명)**가 중요하면 STT가 필요하다(이 스킬 기본 범위 밖 — 필요 시 vlog-highlight의 STT 활용).

### 4.5 작업 리서치 (v3.6.0 신설 — 강화 파이프라인, 디테일·정확도·신뢰도 핵심)
본문을 쓰기 전에 차종·부품·작업을 **웹 검색(구글 등, 네이버에 한정하지 않음)으로 꼼꼼히 조사**해 정확한 사실과 키워드를 확보한다. (헬퍼: WebSearch)

1. **검색 대상**: 차종 제원/세대 코드/엔진, 부품·작업의 원리·효과·주의점, 정확한 수치·규격(PCD·허브경·체결 토크·오일 용량·파이프경 등), 관련 검색 키워드·연관어, 동종 작업 사례.
2. 🚨 **확실하지 않은 정보는 지어내지 않는다.** 검색으로도 확실치 않으면 본문에서 그 수치·주장을 **빼거나 단정하지 않는다.** (예: 사진에 각인 없는 스페이서 두께/파이프 인치는 추정하지 말고 생략)
3. **작성자가 헷갈리거나 모르는 부분은 반드시 웹 검색으로 직접 확인한 뒤 쓴다.** (실사례: "BMW는 휠 너트가 아니라 휠 볼트 체결" — 검색으로 확인해 정정)
4. **수집한 정보는 작성자가 한 번 더 진위를 판단·필터링한다**: 출처 신뢰성, 해당 차종/연식 일치 여부. 거짓·불확실·차종 불일치 정보는 버린다.
5. 리서치 결과를 5단계 본문에 녹여 **디테일·정확도·정보전달력·키워드 선택**을 끌어올린다. 단, 사진으로 확인되는 '실제 그 작업'을 벗어난 일반론 나열은 피한다.

### 4.6 네이버 실검색량 키워드 확인 (제목 SEO 최적화 — /네이버키워드 연동, v+)
제목을 확정하기 전에 네이버 검색광고 키워드도구로 **실제 검색량·경쟁도**를 조회해 제목 키워드를 데이터로 고른다.
1. 차종·작업에서 시드 키워드 2~3개를 만들어 실행:
   ```powershell
   python "C:\Users\MOVEAM_PC\claude-custom-agents\scripts\naver_keywords.py" "<차종+작업>" "<작업통용어>" "<대체검색어>"
   ```
   (예: 아반떼CN7 워커 배기 → `"아반떼배기" "가변배기" "머플러튜닝"`)
2. 결과 `C:/tmp/naver_kw_result.json`(UTF-8)을 **Read**. `keywords[]`는 검색량합계 내림차순 `{kw, pc, mo, total, comp(낮음/중간/높음), pl(파워링크노출수)}`.
3. **작업과 직접 관련되며 검색량 높은 키워드**를 골라 H1 제목 `{메이커 코드명 모델명} 작업명` 의 작업명에 자연스럽게 반영한다(유명 브랜드·통용 검색어 우선, 무관한 연관어는 버림). 제목 양식(중괄호·의도어 금지)은 그대로 지킨다.
4. 🚨 **핵심 키워드를 본문에도 자연스럽게 녹인다**: 위에서 고른 핵심 키워드(차종·작업·브랜드·통용 검색어)를 사진 섹션 서술과 작업요약 문단에 문맥상 자연스럽게 노출한다. 단 **억지 반복·키워드 나열은 네이버 저품질 위험이라 금지** — 정비사가 설명하듯 자연스러운 서술 안에 검색어가 스며들게 한다.
5. (선택) 검색량 상위 + 경쟁 낮음 키워드 2~3개를 마무리 안내에 "추천 검색 키워드"로 한 줄 남길 수 있다.
- ⚠️ API 키(`~/.secrets/naver_searchad.json`)가 없거나 조회 실패하면 **이 단계는 건너뛰고** 기존 SEO 제목 규칙대로 진행한다(작성 중단 금지).

### 6. 출력 형식 (v3.1 — .md 파일 자동 저장 필수)

   - 코드블록 위에 한 줄로 저장 경로 표시:

### 7. 로고 워터마크 + 업로드 정렬 (`_upload` 단일 폴더 통합) (v3.6.4 — 필수)
모든 원본 사진에 좌상단 로고를 합성하면서 **동시에 업로드용 이름으로 `_upload` 폴더에 바로 저장**한다.
**`_upload` 중간 폴더는 만들지 않는다** (사장님 요청: 폴더 하나로 통합). `_upload` 하나가 로고 합성본 + 정렬본이다.

1. 본문 `[사진 N — 부제목]` 순서대로 (원본파일명, 부제목) 추출. 부제목을 **짧은 한글 라벨(2~6자, 공백 없이)** 로 (입고/하부점검/용접/장착/완성 등). 차종 약칭은 넣지 않는다(번호+상황만).
2. `logo_targets.json` 작성: `[{"path":"<폴더>\<원본파일명>","out":"<폴더>\_upload\NN_라벨.jpg"}, ...]` (NN=01,02… 2자리, 본문 순서). **영상(.mp4)은 제외.**
3. 기존 `_upload`가 있으면 내부 파일을 비운 뒤 로고 합성 실행:
   ```powershell
   python "C:\Users\MOVEAM_PC\claude-custom-agents\scripts\logo_watermark.py" "C:\Users\MOVEAM_PC\claude-custom-agents\assets\fervid_logo.png" "C:\tmp\logo_targets.json"
   ```
   → `_upload`에 로고 합성본이 `NN_라벨.jpg`로 바로 저장된다.
4. 로고 기본값: 가로 22%(해상도 무관 자동 스케일), 좌측 0.3% / 상단 0.5%, 약한 그림자. (상수 RATIO/MARGIN_X/MARGIN_Y/SHADOW)
5. 🚨 **본문 사진 파일명 참조 `_(파일명)_` 와 「사진 첨부 순서 체크리스트」 표도 이 `_upload` 새 이름(`NN_라벨.jpg`)으로 맞춘다.** (네이버에서 순서·이름 일치)
6. 결과: `_upload`를 이름순 정렬하면 = 촬영순 = 블로그 첨부 순서. 그대로 드래그&드롭하면 끝.

### 8. 최종 검토 (v3.5 신설 — QA 패스, 필수)
본문 .md 저장 + 로고 합성까지 끝낸 뒤, **완성본을 놓고 사진과 다시 대조하는 "두 번째 눈" 검토를 반드시 1회 수행한다.**
작성하면서 본 1차 판단과 별개로, 다 만든 결과물을 검증하는 단계다. (대량 폴더 일괄 처리 시 폴더마다 수행)

검토 체크리스트(각 항목 통과/수정):
1. **사진 ↔ 섹션 정합성**: 각 `[사진 N]` 섹션을 열어, 해당 파일명 사진을 다시 Read해서 설명이 실제 사진과
   맞는지 확인. (예: "신품 장착 컷"이라 썼는데 실제로는 탈거 컷이면 수정)
2. **작업명/차종/부품명 정확성**: 제목·요약의 작업명, 차량 코드, 부품 브랜드가 메모+사진 근거와 어긋나지 않는가.
   (폴더명만 믿지 말 것 — 폴더명이 틀린 경우가 있다. 예: "직관"이 흡기가 아니라 배기 직관이었던 사례)
3. **톤 6항목 재확인**: 종결어미 ~합니다 통일, 요체/단정 다체 혼입, 문장 길이.
4. **첨부 순서 일치**: 본문 섹션 순서 = 「사진 첨부 순서 체크리스트」 표 순서 = sort_photos.py 정렬 순서.
5. **로고 합성·정렬 누락**: 본문 체크리스트의 모든 사진이 실제 `_upload\`에 로고 합성·정렬(`NN_라벨.jpg`)되어 있고, 본문 파일명 참조가 그 이름과 일치하는가.
6. **해시태그/CTA/구조 누락 없음**: 제목·부제목·구분선·작업요약·효과3·오너팁·CTA·체크리스트·해시태그 전부 존재.
7. **기술적 사실 검증 (v3.5.6 — 발행 신뢰도 직결, 필수)**:
   - **구동방식(FF/FR)**: 전륜구동(FF) 차량(아반떼·SM5·K3·벨로스터 등)에 **추진축(프로펠러 샤프트)·데후(디퍼런셜)** 같은 FR/AWD 전용 부품을 언급하지 말 것. FF차 바닥 중앙의 통은 추진축이 아니라 **센터 머플러(중통)**다. (실제 사고 사례: 아반떼 CN7 본문에 '추진축' 오기)
   - **모델코드 신형/구형**: 같은 차명도 세대별 코드가 다르다. 예) BMW X2 M35i 신형 2세대=**U10**(2024~, 커진 쿠페SUV) vs 구형=F39 / 5시리즈 GT=**F07** / 카마로 세대 등. 사진으로 세대를 확인해 정확한 코드를 쓴다.
   - **장착 전/후·전후면 상태**: 사진이 '장착 완료' 컷인데 '장착 전'으로 쓰거나, 전면을 후면이라 하는 혼동 금지. 사진 실물 상태대로 서술.
   - **엔진/구성**: 베이스 모델과 고성능 모델의 엔진 코드 구분(예: M2 베이스=N55 vs 컴페티션=S55).
   - 🚨 **신품 vs 구품(탈거품) 구분 (정확도 필수 — 사장님 지적 2026-08)**: 부품 신구 비교 컷에서 신품/구품을 절대 혼동하지 말 것.
     - **신품 신호**: 깨끗함·광택, 포장/비닐/박스/라벨/택, 흠집·녹·카본·오일때 없음, 균일한 도장·코팅·기계가공면.
     - **구품(탈거품) 신호**: 오염·먼지·카본·그을음·녹·열변색, 마모·스크래치, 개스킷 눌린 자국, 배관 체결 흔적, 실물 장착 때.
     - 신품을 구품으로(또는 반대로) 쓰지 말 것. **애매하면 '신품/구품' 단정 대신 상태를 그대로 묘사**한다.
   - 🚨 **좌/우 방향 단정 금지**: 한 컷에 신품·구품이 함께 있을 때 '왼쪽=구품/오른쪽=신품' 식으로 **위치를 임의로 단정하지 말 것.** 사진에서 어느 쪽이 신품인지 위 신호로 확실할 때만 좌우를 명시하고, 불명확하면 좌우 표현을 빼고 서술. 완성 후 좌/우(운전석·조수석)도 번호판·핸들·각인 등 근거 없으면 단정 금지.

- 문제를 발견하면 **본문 .md를 수정한 뒤**, 무엇을 고쳤는지 마무리 안내에 1~2줄로 보고한다.
- 문제가 없으면 "최종 검토 통과(N개 섹션, 사진-설명 일치 확인)"를 마무리 안내에 한 줄로 명시한다.


### 8.9 서사·작업 흐름 최종 검토 (필수 — 개별 사진 해석을 넘어 전체 흐름 통합 점검)
본문 QA(8단계)를 마친 뒤, 완성본을 **처음부터 끝까지 하나의 작업기로 통독**하며 전체 작업 흐름을 한 번 더 파악해 개연성·일관성·연관성을 최종 점검한다. (전용 에이전트 `/블로그검토` 와 동일 기준 — 스타일은 유지, 흐름만 다듬는다.)
- 🚨 **개별 사진만 보고 해석하지 말고**, 사진 전체를 순서대로 다시 훑어 "입고→진단→탈거→신품→장착→완성"의 **한 줄기 작업 흐름**을 먼저 재구성한 뒤 각 섹션이 그 흐름에 타당하게 놓였는지 본다.
- **작업 진행 개연성**: 사진(섹션) 순서가 실제 작업 순서로 자연스럽게 이어지는가. 단계 누락·역전·비약이 없는가.
- **앞뒤 연관성**: 각 섹션이 전/후 섹션과 인과로 연결되는가(앞에서 탈거→뒤에서 장착 등). 문맥이 끊긴 곳은 연결어·한 문장으로 잇는다.
- **용어·부품·차종 호칭 일관성**: 같은 부품을 다른 이름으로 부르지 않는가, 차종 코드가 끝까지 일관되는가.
- **상태 모순·중복·누락**: 장착 완료 컷을 '장착 전'으로 쓰지 않았는가, 반복 문단·빠진 연결 설명이 없는가.
- **도입-본문-마무리 논리**: 도입에서 예고한 작업이 본문에서 다뤄지고 마무리에서 정리되는가.
- 🚨 **수정은 최소로**: 스타일·톤·구조·분량은 지금대로 유지하고, 흐름·일관성·개연성에 걸린 부분만 문장 교정/순서 조정/연결어 보강한다. **전면 재작성·스타일 변경·새 정보 창작 금지.** 섹션 순서를 바꾸면 첨부 순서표와 `_upload\` 번호도 함께 맞춘다.
- 고친 내용을 마무리 안내에 1~3줄로 보고한다(없으면 "서사 흐름 점검 통과").

### 9. 마무리 안내 (v3.5.3 갱신)
본문 출력 + .md 저장 + 로고 합성 + 첨부 순서 체크리스트까지 모두 끝난 뒤 다음을 짧게 안내:
- 추정/보강한 부분이 있다면 1~2줄로 표기
- 동영상(.mp4) 있으면 "어디 섹션에 끼울지" 질문 1회
- 사진 일부 생략했으면 그 수치 안내
- 저장된 .md 파일 경로 강조 (복붙 편의)
- **로고 합성된 사진 수 + `_upload\` 폴더 경로 안내** ("총 N장 로고 합성 완료 — _upload\ 폴더가 업로드용 최종본")
- **사진 첨부 순서 체크리스트 작성 완료를 한 줄로 언급** ("총 N장 — .md 끝 체크리스트 표 참조")
- **최종 검토(8단계) 결과를 한 줄로 명시** ("최종 검토 통과 — N개 섹션 사진-설명 일치 확인" 또는 "검토 중 X건 수정: ...")

## 금지 사항
- **`.md` 파일 저장을 생략하지 말 것** (v3.1부터 기본 동작, 사용자 요청 무관)
- **사진 첨부 순서 체크리스트 표를 생략하지 말 것** (v3.3부터 본문 필수 섹션, 해시태그 직전)
- **섹션 헤더에 파일명 렌더링을 빠뜨리지 말 것** (`**[사진 N — 부제목]** _(파일명.jpg)_` 형식 필수)
- **사진 정렬은 반드시 `sort_photos.py` 결과 순서 사용** (v3.4부터 필수). 파일명만 보고 자체 정렬 금지.
- **EXIF 정렬과 파일명 정렬 결과가 다르면 마무리 안내에 한 줄 명시** (사용자가 인지하도록)
- v3.1 톤 위반(요체/단정형 섞임) 시 출력 전 재작성
- 차량/작업이 도저히 불명확하면 → 폴더 스캔 결과 + 메모.txt 요약을 보여주고 사용자에게 차량/작업 확인 1회
- 저장 파일명 임의 변경 금지 (항상 `블로그_본문_v3.1.md`)
- **번호판 모자이크는 하지 않는다** (v3.5.3부터 제거됨). 사진은 원본 그대로 사용한다.
- **로고 워터마크(7단계)를 생략하지 말 것** (v3.5.2부터 기본 동작). 모든 원본 사진에 좌상단 FERVID 로고를 `_upload\`에 합성. `_upload\` 사진이 네이버 업로드용 최종본이다.
- **최종 검토(8단계)를 생략하지 말 것** (v3.5부터 필수). 본문 작성 후 사진↔섹션 정합성·작업명·톤·순서·로고 합성을 반드시 1회 재대조.
- **본문에 영문 'Team FERVID'·마크다운 강조 `**` 를 쓰지 말 것** (v3.5.8). 한글 '팀퍼비드' + 강조기호 없는 평문으로. (네이버 에디터는 마크다운 미지원 → `**`가 별표로 보임)
- **로고 합성·업로드 정렬(7단계)을 생략하지 말 것** (v3.5.8). `_upload`에 `번호_상황.jpg`로 정렬해야 드래그 업로드가 편하다.
