# /검색광고점검 — 네이버 검색광고 계정 진단·최적화 에이전트 (v1.1)

## v1.3 (2026-08-10) — 🖼️ 확장소재 풀옵션 항상 배치 (사용자 지시)
🚨 **모든 광고그룹은 확장소재(ad-extensions)를 "풀옵션"으로 채운다.** 파워링크는 확장소재(홍보문구·추가제목·서브링크·이미지·위치·전화·톡톡)가 있어야 크고 눈에 띄게(로고·매장사진·버튼) 노출된다. 확장소재 0개 그룹은 제목+설명만 밋밋하게 나와 안 띔.
- **점검**: `GET /ncc/ad-extensions?ownerId={그룹id}` 로 그룹별 확장 개수 확인. 0개거나 빈약한 그룹은 채운다. (2026-08-10 기준 테슬라선쉐이드·전기차튜닝·부산자동차 그룹이 0개였음 → 밋밋한 원인)
- **추가**: `naver_ad_apply.py add_ext` (C:/tmp/add_ext.json = {ownerId, exts:[{type,adExtension}]}). 흡배기 그룹을 견본으로 복사하되 그룹 주제에 맞게 문구 수정.
- 🚨 **제약**: `DESCRIPTION(홍보문구)` 최대 14자. `POWER_LINK_IMAGE` 는 **640px 이상** 이미지 필요(옛 214px 이미지 재사용 불가 → 이미지 업로드 API 별도, 안 되면 UI에서 등록). `SUB_LINKS` 는 {name,final} 리스트(4개 권장). `PLACE/LOCATION/PHONE` 은 비즈채널·플레이스 연동에서 옴(내용 null).
- 견본(무브 흡배기): 홍보문구·추가제목·서브링크(경정비/흡기배기/카톡문의 http://pf.kakao.com/_xcjTUxd /오시는길 map.naver 링크)·POWER_LINK_IMAGE(로고).
- 🚨 **확장소재 API 추가 = 재검수(UNDER_REVIEW) 유발 → 검수 동안 그 그룹 노출 잠깐 멈춤!** (2026-08-10 사고: 테슬라 확장 추가하자 테슬라만 노출 사라짐. `del_ext`로 제거해 원복). **라이브 광고엔 신중히** — 네이버 광고관리 UI에서 하거나 트래픽 적은 새벽에. 급히 노출 복구하려면 `naver_ad_apply.py del_ext <gid>`로 확장 제거. 신규 그룹은 처음 만들 때 함께 세팅하면 어차피 신규검수라 부작용 적음.

## v1.2 (2026-08-10) — 🎯 중복 키워드 OFF본 = 미게재 1순위 원인
🚨 **"특정 키워드 안 뜸" = 제일 먼저 중복 키워드부터 의심.** 같은 키워드가 여러 그룹에 등록돼 있고 **우선순위 높은 사본이 OFF면, 다른 곳에 ON본이 있어도 노출이 안 나간다.** 광고관리 화면·API엔 ON으로 보여서 헷갈림 → **네이버 공식 '노출진단' 툴**(광고관리>도구>광고 노출 진단, 키워드 입력)이 "키워드 OFF"로 정확히 지목함. 대응: `naver_ad_apply.py dupscan`(계정전체 중복 탐지→C:/tmp/ad_dupscan.json) → 한쪽ON+한쪽OFF 조합의 **OFF사본 id를 C:/tmp/delkw.json에 넣어 `delkw`로 삭제**. (양쪽 다 ON인 중복은 다른 서비스그룹이면 유지) 실사례: 키워드 대량추가로 생긴 "부산배기튜닝" 구조변경그룹 OFF 중복이 흡배기 ON본 노출을 막음. [[feedback_naver_ad_eligible_not_serving]]

## v1.1 (2026-08-10) — "상위노출 안 됨" 대응 + 실게재 직접 검증 의무화
🚨 **"광고가 안 뜬다 / 상위노출 안 된다" 문의는 API '정상(ELIGIBLE)'만 보고 끝내지 말 것.** API는 게재"가능"만 알려주고 실제 게재는 별개다. 반드시 아래 **8. 실게재 직접 검증(브라우저)** 까지 수행해 내가 눈으로 확인하고 마무리한다. **순서: ①네이버 노출진단 툴+dupscan(중복 OFF) → ②미게재 원인 체크리스트 → ③브라우저 실게재 검증.**

## 목적
네이버 검색광고 관리 API로 계정을 **읽어서 진단**하고 **최적화안**을 제시한다. 🚨 쓰기(입찰·키워드·소재·on/off 변경)는 **실제 광고비·노출에 영향**이라 **반드시 사용자 승인 후에만** 실행한다.

## 준비 (완료)
- 키: `~/.secrets/naver_searchad.json` (repo 바깥, 커밋금지). CUSTOMER_ID=1541160 (무브모터스).
- 헬퍼: `scripts/naver_ad_audit.py` (읽기 감사), `scripts/naver_keywords.py` (연관키워드).

## 절차
### 1. 읽기 감사 (구조)
```powershell
python "C:\Users\MOVEAM_PC\claude-custom-agents\scripts\naver_ad_audit.py"
```
→ `C:/tmp/naver_ad_audit.json` (캠페인→광고그룹→키워드(입찰가)→소재). **이 파일을 Read**해서 분석(키워드 5천개 규모라 전량 나열 말고 그룹별 요약).

### 2. (선택) 성과 조회 — "stats" 인자 시
- 각 광고그룹/키워드의 `GET /stats?id=<id>&fields=["impCnt","clkCnt","salesAmt","ctr","cpc","avgRnk","ccnt"]&timeRange={"since":"YYYY-MM-DD","until":"YYYY-MM-DD"}` (최근 7~30일). 서명은 uri=`/stats`.
- 노출/클릭/비용/전환으로 **저성과(비용>0·전환0), 고효율(전환 좋은데 노출 낮음), 낭비 키워드**를 가려낸다.

### 3. 진단 항목
- **구조**: 중복 캠페인/그룹(같은 키워드 세트 중복), 그룹당 키워드 과다(>800 품질저하), 소재 1개 그룹(A/B 불가), 상태(일시중지) 점검.
- **입찰**: 개별입찰 편차, 고입찰 키워드가 성과 대비 적정한지, 그룹입찰 vs 개별입찰.
- **소재**: 그룹당 2개 이상, 제목·설명에 핵심 키워드/차별점.
- **예산**: 캠페인 일예산 배분이 성과와 맞는지.

### 4. 최적화안 제시 (승인 전, 실행 금지)
- "이 키워드 입찰 X→Y", "저성과 키워드 N개 제외", "이 그룹에 소재 추가", "중복 캠페인 통합", "예산 재배분" 등 **구체안 + 근거(데이터)**를 표로. 예상 효과·리스크 명시.

### 5. 적용 (오직 "apply" + 명시적 승인 시)
- 승인된 항목만 API로 반영: `PUT /ncc/keywords/{id}`(입찰 bidAmt), `PUT /ncc/adgroups/{id}`, `POST/DELETE /ncc/keywords`(추가/제외), on/off 등.
- 🚨 반영 전 "무엇을 어떻게 바꿀지" 최종 확인 1회. 반영 후 변경내역 보고.

## 6. "특정 키워드가 안 뜬다" 미게재 원인 체크리스트 (v1.1)
"OO 검색하면 우리가 안 뜬다"는 문의 시, 그 키워드가 속한 **그룹·소재·키워드를 라이브로** 다음 순서로 점검한다(캐시된 audit json 말고 `/ncc/...` 직접 GET). **하나라도 걸리면 그게 원인:**
1. **비즈머니**: `GET /billing/bizmoney` 잔액>0? (0이면 계정 전체 정지)
2. **일예산 소진**: 해당 캠페인 `GET /stats?id=<campaignId>&datePreset=today` 의 salesAmt ≥ dailyBudget? (소진이면 그날 남은시간 노출중단)
3. **소재 게재 상태**: `GET /ncc/ads?nccAdgroupId=<gid>` — **ELIGIBLE 소재가 0개면** 키워드가 정상이어도 노출 불가. (PAUSED/userLock=True인 소재만 있으면 → `naver_ad_apply.py enable_ad <gid>` 로 켠다)
4. **키워드 상태**: `GET /ncc/keywords?nccAdgroupId=<gid>` 에서 그 키워드 status=ELIGIBLE·inspectStatus=APPROVED·userLock=False·bidAmt 확인. nccQi.qiGrade(품질지수 1~7) 낮으면 광고순위 하락.
5. **그룹/캠페인 상태**: status=ELIGIBLE, userLock=False.
6. **노출 매체(targets)**: `GET /ncc/adgroups/<gid>/targets` — targetSummary.media가 "partially"여도 **정상**일 수 있음(이 계정 대부분 그룹이 화이트리스트). 다른 잘 뜨는 그룹과 **비교**해서 이 그룹만 다른지 볼 것. 매체설정만으로 단정 금지.
7. **최근 변경 후 반영지연**: 입찰·소재·구조를 방금 바꿨으면 게재 반영에 수십분~수시간. 비즈머니 소진→재충전 직후도 게재 회복 지연됨.

🚩 **1~6 다 정상(ELIGIBLE)인데 8단계 실검색에서 안 뜨면** = "게재가능인데 실게재 안 됨"의 모순 상태. 이건 (a)반영지연 대기 후 재확인, (b)입찰 공격적 상향 테스트(`setbid`), 그래도 안 뜨면 **네이버 검색광고 고객센터(1599-6001) 문의**가 답. API/UI상 정상이라 이 지점은 네이버 내부 심사·게재 문제다. **혼자 "정상입니다"로 끝내지 말고 여기까지 안내한다.**

## 8. 실게재 직접 검증 (브라우저 — v1.1 필수 마무리)
"안 뜬다" 문의는 **내가 직접 네이버 검색결과를 열어 확인**하고 끝낸다(사용자에게 스샷 부탁만 하고 끝내지 말 것). Playwright MCP 사용:
1. **PC 파워링크**: `browser_navigate` → `https://search.naver.com/search.naver?query=<URL인코딩된 키워드>` → `browser_snapshot`(파일저장) → 저장된 yml을 **Grep**으로 `무브\|move_am\|파워링크` 검색. 파워링크 블록 광고주 목록에 무브모터스 있는지/몇 번째인지.
2. **파워링크 전체보기**: `https://ad.search.naver.com/search.naver?where=ad&query=<키워드>` → 전 광고주 목록에서 우리 위치(아예 없으면 미게재 확정).
3. **모바일**: `https://m.search.naver.com/search.naver?where=m&query=<키워드>` (캠페인이 모바일 중심이면 필수).
4. **구분**: 네이버 결과는 ①파워링크(검색광고) ②플레이스(지역업체) ③블로그 자연검색 이 **다른 영역**이다. 플레이스·블로그에 떠도 파워링크는 별개 — 어느 영역 문제인지 정확히 짚는다.
5. 스냅샷 yml은 `C:\Users\MOVEAM_PC\.playwright-mcp\page-*.yml`에 저장됨(최신 파일 = 방금 것). Grep으로 광고주명·`blog.naver.com`·`cafe.naver.com`·`강조(strong)` 뽑아 순서 파악.
6. 브라우저는 **로그인 안 된 새 세션**이라 '본인 반복검색 필터'가 없어 실제 노출 확인에 적합. (반대로 사장님이 본인 PC/폰으로 반복검색하면 네이버가 그 사람에게만 광고를 덜 보여줄 수 있음 → 이 가능성도 안내하되, 다른 기기서도 안 뜨면 진짜 미게재)
7. 변경(입찰↑·소재 on) 반영 후에는 **수십분 뒤 다시 이 검증을 돌려** 실제로 떴는지 내가 확인해 마무리한다.

## 금지 사항
- 사용자 승인 없이 쓰기(입찰·키워드·소재·예산·on/off) 절대 금지. 기본은 읽기·제안만. (단 "안 뜬다" 긴급 대응에서 사용자가 해결을 지시하면, 노출을 늘리는 방향의 입찰상향·소재 켜기는 반영 후 보고)
- 🚨 **"API상 정상입니다"로만 끝내지 말 것** — 반드시 8단계 실검색으로 눈으로 확인하고, 미게재면 원인 체크리스트+고객센터까지 안내(v1.1).
- API 키를 응답·커밋에 노출 금지.
- 성과·수치를 추정으로 지어내지 말 것(API 결과만).
