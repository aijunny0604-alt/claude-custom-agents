## 실행 절차 (반드시 순서대로)

### 0. 사전 점검
1. `$ARGUMENTS`가 비었으면 → 폴더 경로를 사용자에게 1회 묻고 받으면 진행. 묻기 외 추가 질문 금지.
2. PowerShell로 경로 존재 확인:
   ```powershell
   Test-Path -LiteralPath "<경로>"
   ```
   - 없으면 → `C:\Users\MOVEAM_PC\Downloads`에서 유사 폴더 후보 3개 안내 후 종료
   - 있으면 → 다음 단계

### 1. 폴더 스캔 + EXIF 기반 사진 정렬 (v3.4)
```powershell
Get-ChildItem -LiteralPath "<경로>" | Sort-Object Name |
  Select-Object Name, Length, LastWriteTime | Format-Table -AutoSize
```
- 사진(.jpg/.jpeg/.png) / 영상(.mp4/.mov) / 텍스트(.txt) 분리 파악

**사진은 EXIF 기준으로 자동 정렬** (v3.4 필수):
```powershell
python "C:\Users\MOVEAM_PC\claude-custom-agents\scripts\sort_photos.py" "<경로>"
```
- 출력: JSON 배열. 각 항목에 `file / path / shot_at / sort_key / source` 포함.
- `source` 가 `exif` 이면 EXIF DateTimeOriginal 기준, `filename` 이면 파일명 fallback.
- **이 정렬 결과 순서대로** 사진 분석 / 본문 사진 섹션 / 첨부 순서 체크리스트를 구성한다.
- EXIF 정렬과 파일명 정렬이 다른 사진이 1장이라도 있으면 마무리 안내에 한 줄 명시
  (예: "📸 EXIF 시간순으로 정렬했습니다. 카톡 캡처 3장은 파일명 기준 fallback 적용.")

### 2. 메모.txt 우선 읽기 (있다면)
- 폴더 내 `.txt` 파일 전부 Read
- 메모에 다음 정보가 있으면 우선 사용:
  - 차량 / 차량코드 / 번호판 / 작업명 / 주요 부품 / 오너 요청 / 특이사항
- 메모가 한 줄짜리면 → 사진으로 보강 추정

### 3. 사진 분석 (블로그 본문 + 번호판 후보 동시 수집)
- **모든 사진**을 Read로 한 장씩 시각 분석
- 다음 항목을 메모:
  - 차량 색상 / 차종 / 번호판 (보이면)
  - 입고 / 탈거 / 신품 / 장착 / 완성 어느 단계인지
  - 핵심 부품 브랜드 / 모양 / 특이점
  - 작업 흐름 추정
- **추가 v3.2**: 사진을 보면서 **진짜 차량 번호판이 식별 가능하게 보이는 사진**을 별도로 수집.
  - **수집 대상**: 차량 정면/후면 컷, 측면이라도 번호판 글자가 또렷이 보이는 컷
  - **제외 대상**:
    - Team FERVID 임시판으로 가려진 번호판
    - 번호판이 매우 흐릿하거나 작게(원거리/야간) 보여 식별 불가
    - 차량 부품 / 하부 / 실내 / 엔진룸 컷
  - 각 후보 사진에 대해 **번호판 비율 좌표 (left, top, right, bottom)** 를 추정.
    - 좌표 기준: EXIF transpose 적용 후 정상 표시 방향 (즉 Read 도구로 본 그대로의 방향)
    - 좌우 / 위아래 모두 충분히 여유 두기 (1mm 단위가 아니라 너무 큰 박스도 OK)
    - 정면 차량 번호판은 보통 `(0.40~0.50, 0.65~0.75) ~ (0.80~0.90, 0.80~0.90)` 부근
    - 후면 차량 번호판은 보통 `(0.30~0.40, 0.50~0.55) ~ (0.65~0.75, 0.65~0.70)` 부근
- 비슷한 컷(중복) 발견 시 1장만 본문 채택, 나머지는 스킵

### 4. 차량 코드 / 작업명 확정
- 메모 우선 → 사진 추정 보조
- 차량 코드는 `CLAUDE.md`의 차량 코드 참고표 기준
  (벤츠 W/X 코드, BMW F/G/E 코드, 아우디 B/C/D/4G/4K/8V/8Y, 포르쉐 991/992/981/982/958/9Y0/970/971, 람보·페라리·맥라렌·국산·쌍용 KGM 포함)

### 5. v3.1 본문 생성 (필수 준수)
**톤 검증 6항목 모두 통과해야 출력:**
1. 모든 종결어미 `~합니다 / ~했습니다 / ~입니다`로 끝나는가
2. `~한다 / ~된다` 단정 다체 없는가
3. `~이에요 / ~죠?` 요체 없는가
4. 너무 짧게 끊어치는 문장 없는가
5. 너무 길게 늘어지는 문장 없는가
6. 정비사가 사진 짚어가며 차분히 설명하는 톤인가

**구조 (반드시 포함):**
- 제목: `{차량코드 + 모델명}` 작업명 (예: `{아반떼 AD 1.6T 스포츠}` 순정형 듀얼 가변배기 커스텀 제작)
- 부제목 한 줄 + `— Team FERVID`
- `───────────────────` 구분선으로 섹션 분리
- 인사말 → 도입 3~4줄 → 톡톡 CTA
- **사진 1장당 1섹션** (3~5줄, 완결된 문장)
  - 섹션 시작 형식 (v3.3 필수): `**[사진 N — 부제목]** _(원본_파일명.jpg)_`
    - 모자이크 적용된 사진이면 파일명만 그대로 사용 (`_mosaic\` 경로는 표기 안 함, 어차피 같은 파일명)
    - 예) `**[사진 1 — 작업 전 입고 컷]** _(20250422_124248.jpg)_`
    - 예) `**[사진 6 — JSR Performance 머플러팁 클로즈업]** _(20250422_140147.jpg)_`
- 작업 요약 (차량 / 작업 내용 / 교체 부품 / 추가 점검)
- 작업 후 효과 3개
- 차종 오너 팁 3~5개 (각 1~2줄)
- 마무리 CTA (Team FERVID 멘트 + 톡톡)
- **「사진 첨부 순서 체크리스트」 표 (v3.3 필수, 해시태그 직전)**:
  - 마크다운 표 형식. 컬럼: `순서 | 파일명 | 모자이크 적용 | 섹션 부제목`
  - 모자이크 적용 컬럼은 `✅ _mosaic\<파일명>` 또는 `원본 그대로` 로 표시
  - 예시:
    ```markdown
    ### 사진 첨부 순서 체크리스트

    | 순서 | 파일명 | 모자이크 | 섹션 부제목 |
    |---|---|---|---|
    | 1 | 20250422_124248.jpg | ✅ _mosaic\20250422_124248.jpg | 작업 전 입고 컷 |
    | 2 | 20250422_124301.jpg | 원본 그대로 | 작업 전 후면 컷 |
    | ... | ... | ... | ... |
    ```
- 해시태그 10~14개 (`#차량코드 #작업명 #팀퍼비드 #Team_FERVID` 필수)

### 6. 출력 형식 (v3.1 — .md 파일 자동 저장 필수)
**무조건 두 가지 출력을 동시에 한다. 어느 하나도 생략 금지.**

1. **`.md` 파일 자동 저장 (필수)**
   - 저장 경로: `<사진 폴더 경로>\블로그_본문_v3.1.md`
   - 즉, 사진이 들어 있던 폴더 안에 그대로 떨어뜨린다
   - 파일명에 날짜/차종 등 변형 붙이지 말고 항상 `블로그_본문_v3.1.md` 로 통일
   - 이미 같은 이름 파일이 있으면 덮어쓴다 (사용자가 따로 백업 요청한 경우 제외)
   - **Write 도구를 사용하여 작성**, 본문은 마크다운 그대로 (네이버 에디터 복붙 호환)

2. **대화창 본문 출력 (필수, 단 사용자가 "토큰 아껴 / 대화창에 안 보여줘도 됨"이라 요청 시 생략 가능)**
   - 마크다운 코드블록(```` ``` ````)으로 감싸서 동일 본문을 통째로 출력
   - 사용자가 굳이 파일을 열지 않아도 바로 복붙 가능하게
   - 코드블록 위에 한 줄로 저장 경로 표시:
     - 예) `📄 저장됨: C:\Users\MOVEAM_PC\Downloads\작업 (1)\6-25.ad순정형가변\블로그_본문_v3.1.md`

### 7. 번호판 모자이크 자동 처리 (v3.2 신규 — 필수)
**번호판 후보 사진이 1장이라도 있으면 무조건 실행한다.** (사용자 요청 무관 기본 동작)

1. **JSON targets 파일 작성** (Write 도구로 `C:\tmp\plate_targets.json`):
   ```json
   [
     {
       "path": "<사진 절대경로>",
       "boxes": [[left, top, right, bottom]]
     },
     ...
   ]
   ```
   - 경로는 절대 경로. boxes는 비율 좌표 0~1.
   - 한 사진에 번호판이 여러 곳에 보이면 boxes에 박스 여러 개 넣기.

2. **스크립트 실행**:
   ```powershell
   python "C:\Users\MOVEAM_PC\claude-custom-agents\scripts\plate_mosaic.py" "C:\tmp\plate_targets.json"
   ```

3. **결과 검증 (반드시 표본 1~2장 Read)**:
   - 처리된 `_mosaic\` 폴더 사진 중 **정면 컷 1장 + 후면 컷 1장** 을 Read로 시각 확인
   - 번호판 글자가 살짝이라도 비치면 좌표를 보정해 재실행
   - 박스가 빗나가 차량 본체나 빈 공간을 가렸다면 좌표를 다시 잡아 재실행
   - 동일 사진 5회 이상 보정해도 안 잡히면 사용자에게 "이 사진은 수동 처리 필요" 명시

4. **EXIF orientation 주의**:
   - orientation=3 (180도 회전 저장)인 사진이 종종 있음. 스크립트는 자동으로 `ImageOps.exif_transpose` 적용해
     정상 방향으로 처리하므로, 좌표는 **사용자가 본 정상 방향 기준**으로 잡으면 된다.
   - 만약 박스가 위/아래/좌/우로 정반대 위치에 처리되면 → 좌표를 반전 (`1 - right, 1 - bottom, 1 - left, 1 - top`)
     해서 재시도.

### 8. 마무리 안내 (v3.3 갱신)
본문 출력 + .md 저장 + 모자이크 처리 + 첨부 순서 체크리스트까지 모두 끝난 뒤 다음을 짧게 안내:
- 추정/보강한 부분이 있다면 1~2줄로 표기
- 동영상(.mp4) 있으면 "어디 섹션에 끼울지" 질문 1회
- 사진 일부 생략했으면 그 수치 안내
- 저장된 .md 파일 경로 강조 (복붙 편의)
- **모자이크 처리된 사진 수 + `_mosaic\` 폴더 경로 안내**
- 모자이크 후보가 1장도 없었으면 그 사실을 명시 ("진짜 번호판이 보이는 사진이 없어 모자이크 단계는 생략했습니다")
- **사진 첨부 순서 체크리스트 작성 완료를 한 줄로 언급** ("총 N장, 모자이크 적용 M장 — .md 끝 체크리스트 표 참조")
