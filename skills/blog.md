## 실행 절차 (반드시 순서대로)

### 0. 사전 점검
1. `$ARGUMENTS`가 비었으면 → 폴더 경로를 사용자에게 1회 묻고 받으면 진행. 묻기 외 추가 질문 금지.
2. PowerShell로 경로 존재 확인:
   ```powershell
   Test-Path -LiteralPath "<경로>"
   ```
   - 없으면 → `C:\Users\MOVEAM_PC\Downloads`에서 유사 폴더 후보 3개 안내 후 종료
   - 있으면 → 다음 단계

### 1. 폴더 스캔 + EXIF 기반 사진 정렬 (v3.4)
```powershell
Get-ChildItem -LiteralPath "<경로>" | Sort-Object Name |
  Select-Object Name, Length, LastWriteTime | Format-Table -AutoSize
```
- 사진(.jpg/.jpeg/.png) / 영상(.mp4/.mov) / 텍스트(.txt) 분리 파악

**사진은 EXIF 기준으로 자동 정렬** (v3.4 필수):
```powershell
python "C:\Users\MOVEAM_PC\claude-custom-agents\scripts\sort_photos.py" "<경로>"
```
- 출력: JSON 배열. 각 항목에 `file / path / shot_at / sort_key / source` 포함.
- `source` 가 `exif` 이면 EXIF DateTimeOriginal 기준, `filename` 이면 파일명 fallback.
- **이 정렬 결과 순서대로** 사진 분석 / 본문 사진 섹션 / 첨부 순서 체크리스트를 구성한다.
- EXIF 정렬과 파일명 정렬이 다른 사진이 1장이라도 있으면 마무리 안내에 한 줄 명시
  (예: "📸 EXIF 시간순으로 정렬했습니다. 카톡 캡처 3장은 파일명 기준 fallback 적용.")

### 2. 메모.txt 우선 읽기 (있다면)
- 폴더 내 `.txt` 파일 전부 Read
- 메모에 다음 정보가 있으면 우선 사용:
  - 차량 / 차량코드 / 번호판 / 작업명 / 주요 부품 / 오너 요청 / 특이사항
- 메모가 한 줄짜리면 → 사진으로 보강 추정

### 3. 사진 분석 (블로그 본문용)
- **모든 사진**을 Read로 한 장씩 시각 분석
- 다음 항목을 메모:
  - 차량 색상 / 차종
  - 입고 / 탈거 / 신품 / 장착 / 완성 어느 단계인지
  - 핵심 부품 브랜드 / 모양 / 특이점
  - 작업 흐름 추정
- 비슷한 컷(중복) 발견 시 1장만 본문 채택, 나머지는 스킵

### 4. 차량 코드 / 작업명 확정
- 메모 우선 → 사진 추정 보조
- 차량 코드는 `CLAUDE.md`의 차량 코드 참고표 기준
  (벤츠 W/X 코드, BMW F/G/E 코드, 아우디 B/C/D/4G/4K/8V/8Y, 포르쉐 991/992/981/982/958/9Y0/970/971, 람보·페라리·맥라렌·국산·쌍용 KGM 포함)

### 5. v3.1 본문 생성 (필수 준수)
**톤 검증 6항목 모두 통과해야 출력:**
1. 모든 종결어미 `~합니다 / ~했습니다 / ~입니다`로 끝나는가
2. `~한다 / ~된다` 단정 다체 없는가
3. `~이에요 / ~죠?` 요체 없는가
4. 너무 짧게 끊어치는 문장 없는가
5. 너무 길게 늘어지는 문장 없는가
6. 정비사가 사진 짚어가며 차분히 설명하는 톤인가

**명칭 규칙 (v3.5.1 — 현장 통용 키워드 우선, 필수):**
- 부품·작업 명칭은 **정비 현장에서 실제로 쓰고 네이버에서 검색되는 통용어**를 메인으로 쓴다. 정식 학술명/영문 풀네임만 단독으로 쓰지 말 것.
- 통용어와 정식명이 다르면 **통용어(메인) + 정식명(괄호 보조)** 형식: 예) `방열판(히트실드)`, `행거(머플러 행거)`, `데후(디퍼렌셜)`.
- 현장어 ↔ 정식명 예시집 (사진에 해당 부품이 보이면 통용어로 표기):
  - 행거 = 머플러/배기 행거(exhaust hanger)
  - 방열판 = 열 차단판(heat shield)
  - 데후 = 디퍼렌셜(differential)
  - 자바라 = 배기 플렉시블(주름관)
  - 중통 = 센터 파이프(중간 머플러)
  - 직관 = 직선 배기관(촉매/레조네이터 제거 파이프)
  - 외벨트 = 드라이브벨트(구동벨트)
  - 미미 = 엔진 마운트
  - 쇼바 = 쇼크업소버(댐퍼)
  - 부싱 = 부싱(고무 마운트류는 그대로 통용)
- 단, **차종/부품 브랜드명은 정확히** (JSR, 카프리스토, H&R, AEM, 디토즈, RW 등). 브랜드를 통용어로 뭉개지 말 것.
- 해시태그에도 통용 검색어를 넣는다(예: `#머플러행거 #방열판 #직관배기`).

- `───────────────────` 구분선으로 섹션 분리
- 인사말 → 도입 3~4줄 → 톡톡 CTA

### 6. 출력 형식 (v3.1 — .md 파일 자동 저장 필수)
**무조건 두 가지 출력을 동시에 한다. 어느 하나도 생략 금지.**

1. **`.md` 파일 자동 저장 (필수)**
   - 저장 경로: `<사진 폴더 경로>\블로그_본문_v3.1.md`
   - 즉, 사진이 들어 있던 폴더 안에 그대로 떨어뜨린다
   - 파일명에 날짜/차종 등 변형 붙이지 말고 항상 `블로그_본문_v3.1.md` 로 통일
   - 이미 같은 이름 파일이 있으면 덮어쓴다 (사용자가 따로 백업 요청한 경우 제외)
   - **Write 도구를 사용하여 작성**, 본문은 마크다운 그대로 (네이버 에디터 복붙 호환)

2. **대화창 본문 출력 (필수, 단 사용자가 "토큰 아껴 / 대화창에 안 보여줘도 됨"이라 요청 시 생략 가능)**
   - 마크다운 코드블록(```` ``` ````)으로 감싸서 동일 본문을 통째로 출력
   - 사용자가 굳이 파일을 열지 않아도 바로 복붙 가능하게
   - 코드블록 위에 한 줄로 저장 경로 표시:
     - 예) `📄 저장됨: C:\Users\MOVEAM_PC\Downloads\작업 (1)\6-25.ad순정형가변\블로그_본문_v3.1.md`

### 7. 좌상단 FERVID 로고 워터마크 (v3.5.2 신설 — 필수)
모든 사진(원본)에 좌측 상단 FERVID 로고를 일괄 합성한다. (PhotoScape 수동 작업 대체)

1. **대상 사진**: 폴더 안의 원본 이미지 전부 (영상/.txt 제외). 모자이크는 더 이상 적용하지 않으므로 항상 원본을 입력으로 쓴다.
2. **로고 합성 실행**:
   ```powershell
   python "C:\Users\MOVEAM_PC\claude-custom-agents\scripts\logo_watermark.py" "C:\Users\MOVEAM_PC\claude-custom-agents\assets\fervid_logo.png" "C:\tmp\logo_targets.json"
   ```
   - `logo_targets.json` 형식: `[{"path":"<원본 절대경로>","out":"<폴더>\_logo\<파일명>"}, ...]`
   - 결과는 각 작업 폴더의 `_logo\` 하위에 저장된다. **이 `_logo\` 사진이 네이버 업로드용 최종본**이다.
3. **기본값**: 로고 폭 = 사진 가로 22%(해상도 무관 자동 스케일), 좌측 여백 0.3% / 상단 0.5%(좌상단 모서리에 바짝), 약한 그림자(밝은 차체에서도 보이게). 조정은 스크립트 상수(RATIO/MARGIN_X/MARGIN_Y/SHADOW)로.
4. **대량 폴더 일괄**: 폴더 전체를 순회해 한 번에 처리하려면 `run_logo_all.py` 패턴(폴더 순회 → 원본 → _logo 출력)을 쓴다.

### 8. 최종 검토 (v3.5 신설 — QA 패스, 필수)
본문 .md 저장 + 로고 합성까지 끝낸 뒤, **완성본을 놓고 사진과 다시 대조하는 "두 번째 눈" 검토를 반드시 1회 수행한다.**
작성하면서 본 1차 판단과 별개로, 다 만든 결과물을 검증하는 단계다. (대량 폴더 일괄 처리 시 폴더마다 수행)

검토 체크리스트(각 항목 통과/수정):
1. **사진 ↔ 섹션 정합성**: 각 `[사진 N]` 섹션을 열어, 해당 파일명 사진을 다시 Read해서 설명이 실제 사진과
   맞는지 확인. (예: "신품 장착 컷"이라 썼는데 실제로는 탈거 컷이면 수정)
2. **작업명/차종/부품명 정확성**: 제목·요약의 작업명, 차량 코드, 부품 브랜드가 메모+사진 근거와 어긋나지 않는가.
   (폴더명만 믿지 말 것 — 폴더명이 틀린 경우가 있다. 예: "직관"이 흡기가 아니라 배기 직관이었던 사례)
3. **톤 6항목 재확인**: 종결어미 ~합니다 통일, 요체/단정 다체 혼입, 문장 길이.
4. **첨부 순서 일치**: 본문 섹션 순서 = 「사진 첨부 순서 체크리스트」 표 순서 = sort_photos.py 정렬 순서.
5. **로고 합성 누락**: 본문 체크리스트의 모든 사진이 실제 `_logo\`에 로고 합성되어 있는가.
6. **해시태그/CTA/구조 누락 없음**: 제목·부제목·구분선·작업요약·효과3·오너팁·CTA·체크리스트·해시태그 전부 존재.

- 문제를 발견하면 **본문 .md를 수정한 뒤**, 무엇을 고쳤는지 마무리 안내에 1~2줄로 보고한다.
- 문제가 없으면 "최종 검토 통과(N개 섹션, 사진-설명 일치 확인)"를 마무리 안내에 한 줄로 명시한다.

### 9. 마무리 안내 (v3.5.3 갱신)
본문 출력 + .md 저장 + 로고 합성 + 첨부 순서 체크리스트까지 모두 끝난 뒤 다음을 짧게 안내:
- 추정/보강한 부분이 있다면 1~2줄로 표기
- 동영상(.mp4) 있으면 "어디 섹션에 끼울지" 질문 1회
- 사진 일부 생략했으면 그 수치 안내
- 저장된 .md 파일 경로 강조 (복붙 편의)
- **로고 합성된 사진 수 + `_logo\` 폴더 경로 안내** ("총 N장 로고 합성 완료 — _logo\ 폴더가 업로드용 최종본")
- **사진 첨부 순서 체크리스트 작성 완료를 한 줄로 언급** ("총 N장 — .md 끝 체크리스트 표 참조")
- **최종 검토(8단계) 결과를 한 줄로 명시** ("최종 검토 통과 — N개 섹션 사진-설명 일치 확인" 또는 "검토 중 X건 수정: ...")

## 금지 사항
- **`.md` 파일 저장을 생략하지 말 것** (v3.1부터 기본 동작, 사용자 요청 무관)
- **사진 첨부 순서 체크리스트 표를 생략하지 말 것** (v3.3부터 본문 필수 섹션, 해시태그 직전)
- **섹션 헤더에 파일명 렌더링을 빠뜨리지 말 것** (`**[사진 N — 부제목]** _(파일명.jpg)_` 형식 필수)
- **사진 정렬은 반드시 `sort_photos.py` 결과 순서 사용** (v3.4부터 필수). 파일명만 보고 자체 정렬 금지.
- **EXIF 정렬과 파일명 정렬 결과가 다르면 마무리 안내에 한 줄 명시** (사용자가 인지하도록)
- v3.1 톤 위반(요체/단정형 섞임) 시 출력 전 재작성
- 차량/작업이 도저히 불명확하면 → 폴더 스캔 결과 + 메모.txt 요약을 보여주고 사용자에게 차량/작업 확인 1회
- 저장 파일명 임의 변경 금지 (항상 `블로그_본문_v3.1.md`)
- **번호판 모자이크는 하지 않는다** (v3.5.3부터 제거됨). 사진은 원본 그대로 사용한다.
- **로고 워터마크(7단계)를 생략하지 말 것** (v3.5.2부터 기본 동작). 모든 원본 사진에 좌상단 FERVID 로고를 `_logo\`에 합성. `_logo\` 사진이 네이버 업로드용 최종본이다.
- **최종 검토(8단계)를 생략하지 말 것** (v3.5부터 필수). 본문 작성 후 사진↔섹션 정합성·작업명·톤·순서·로고 합성을 반드시 1회 재대조.
