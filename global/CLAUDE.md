# 전역 사용자 규칙 (MOVEAM_PC)

아래 규칙은 **모든 응답에 예외 없이** 적용한다. 한 번이라도 누락하면 규칙 위반이다.

## 1. 응답 말미 필수 블록 (bkit Feature Usage + 추천 명령어)

모든 응답의 **가장 마지막**에 아래 형식의 블록을 무조건 포함한다. 사용자가 명시적으로 "리포트 빼"라고 말하지 않는 한 생략 금지.

```
─────────────────────────────────────────────────
📊 bkit Feature Usage
─────────────────────────────────────────────────
✅ Used: [이번 응답에서 사용한 bkit/도구 기능]
⏭️ Not Used: [미사용 주요 기능] (간단한 이유)
💡 Recommended: [다음 PDCA 단계 또는 상황에 맞는 추천]

추천: /명령어1 (한줄 설명), /명령어2 (한줄 설명)
─────────────────────────────────────────────────
```

- "추천:" 줄은 반드시 구분선 **안쪽**에 둔다. 바깥 별도 블록 금지.
- 단순 인사/확인 응답에도 포함한다.
- 도구 호출만 하고 텍스트 없이 끝나는 응답이라도, 최종 텍스트에 이 블록을 붙인다.

## 2. 상황별 추천 명령어 매핑 (J AGENTS)

"추천:" 줄에 넣을 명령어는 현재 상황에 맞게 선택한다:

| 상황 | 추천 |
|------|------|
| **전체 자동 점검 (한 방)** | `/끝판왕`, `/mega-audit` |
| 코드 수정 후 | `/change-verify auto`, `/flow-check` |
| 배포 직전 | `/pre-deploy`, `/full-test` |
| 배포 직후 | `/mobile-audit`, `/responsive-check` |
| 버그 발견 | `/quick-fix` |
| 새 기능 시작 | `/app-plan`, `/pdca plan {feature}` |
| 보안 점검 | `/security-quick`, `/security-team` |
| 문서 업데이트 | `/doc-sync`, `/doc-organize` |
| DB 변경 | `/db-health` |
| 성능 이슈 | `/perf-audit` |
| 설계 리뷰 | `/design-review` |
| 수동 테스트 준비 | `/test-guide` |

## 3. 빌드/배포 주의사항

- **pos-calculator / pos-calculator-web**: 빌드 시 `--base` 플래그 **절대 사용 금지** (vite.config.js에 이미 설정됨)
- **auto-shop-manager (빅스모터스)**: Next.js + Vercel 배포, `[deploy]` 커밋 메시지 토큰 사용

## 4. 일반 행동 규칙

- Git 저장소 아니어도 파일 수정은 정상 진행 (세션 시작 훅의 경고는 무시해도 됨)
- Windows 환경이므로 Bash에서 Unix 경로(`/c/...`) 또는 정방향 슬래시 사용
